# 斜杠命令回执、工具超时与脚本流式输出

Status: implemented 2026-09-18. 四条来自 Ral 对会话
`20260918141107962-j3fu88a87tamu6k8jee` 的复盘。

## 1 ·「/view_context 打印的内容会进上下文么」—— 不会

`/view_context`、`/copy_session_path`、压缩提示走的都是 `appendLocalNotice`,它建的消息带着
`promptExcluded: true, localOnly: true`。两个标记都是**真的被执行的**,不是装饰:

- `promptExcluded` 在 token 计数处直接返回空串,在历史筛选处被排除;
- `localOnly` 让它从不落库(`persisted` 过滤、保存时跳过)。

所以「copied 448,593 chars · ~112.1k tok · 10 history entries」这一行只给人看,模型一个字都收不到。
**不需要改。** 记在这里是因为这个问题会反复出现 —— 它长得太像模型的正文了,而那正是第 4 条。

## 2 · 宿主不再给工具调用设 120 秒墙钟

Ral:「超时是工具层面的 120s,我们工具调用不该设置超时,如果工具自己内部超时报错,我们捕获并提示才对」。

`BaseAgent.withToolTimeout` 以前对**所有**工具兜底 `120_000`。初衷(卡住的工具不该悄悄冻住回合)
是对的,落点错了:120 秒对 `read_file` 是天荒地老,对一次同步几十个 submodule 的脚本只是刚开始。
更糟的是**被切断时工具本身还在跑** —— 宿主只是不再看着它,模型却收到「timed out」,
于是模型以为没发生的事其实正在发生。日志里那次 255 秒的等待就是这个形状。

现在:只有工具**自己声明**了预算(`spec.timeoutMs`,例如技能脚本 60s),或运维显式设了
`COACH_TOOL_TIMEOUT_MS` 想统一钳住,才计时;都没有就不计时,由工具自己的超时/错误冒上来,
宿主捕获并如实转述。**回合墙钟(默认 600s)和 Stop 都没动** —— 去掉的是「按工具一刀切」那一层。

## 3 · 技能脚本跑着的时候就有反馈

Ral:「技能脚本执行过程中,要能依据打印,给用户持续的反馈,而不是脚本执行完了一次性给反馈」。

两侧的脚本运行器都新增 `onOutput(line, stream)`,`run_skill_file` 把它接到活动条上。

- **按整行回调**,不是按 chunk:chunk 边界不是行边界,直接转发会把一行劈成两条、或把十行挤成一条。
- **结尾没有换行的那一行也要冲出来** —— 脚本最后一句常常就是结论。
- **封顶**:最多 200 行、每行 300 字符,一个话多的脚本不该把活动条刷爆。
- **只进活动条,不进提示词**:这些是给人看的进度,再喂回模型只会挤占上下文;模型拿到的仍然是
  收尾时那一份完整 stdout/stderr,**一个字节都没变**(有用例专门钉这一条)。

## 4 · 斜杠命令的回执改成淡灰

Ral:「这种快捷指令的输出改成淡灰色文字和 ai 主要回答区分开」。

`appendLocalNotice` 建的消息是 `role: 'ai'`,所以「copied … chars」「Session path copied: …」
和模型的正文长得一模一样 —— 这也是第 1 条会被怀疑的原因。判据用 `localOnly`(只有这类消息带它),
**不是按文案匹配**:按文案匹配下一条命令换个措辞就静默失效。

- cowork:`messageBubbleTint` 加一支 `text-gray-400`,排在 error 之后(报错回执仍然是红的)。
- bitterless:`message-item__bubble--notice`,`color: #9ca3af`。
