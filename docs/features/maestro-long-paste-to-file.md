# FEATURE · 超长粘贴转临时文件

> 实现 `agent/longPaste.service.ts` · 接线 `maestroAgent.service.sendAgentMessage()` · 守卫 `check-long-paste.mjs`
> Ral 2026-09-11：「当用户粘贴的文字大小超过一定 size 时 作为临时文件放到提示词中」、
> 「需要 `<userData>` 下有目录能存放这种文件」

## 为什么需要它

它和「**用户消息不能被压缩**」是同一条需求的两半。既然用户原话按设计逐字保留、永不进摘要，
那么一次几十万字符的粘贴就会**永久**占住上下文 —— 压缩帮不了它，因为压缩按设计不碰它。
唯一的出路是让它一开始就不以正文形态进上下文。

## 规则

| | 取值 | 理由 |
|---|---|---|
| 阈值 | **20,000 字符**（≈ 5k token） | 从「留下来的代价」反推：用户原话链预算 12k token，一条 5k token 的消息会永久吃掉其中 40%，且永不被摘要。低于这个量级留在正文里更有用 —— 转文件反而多一次工具往返 |
| 判据 | **严格大于** | 恰好等于阈值不转 |
| 目录 | `<userData>/pastes/` | Ral 指定。**不放 `<userData>/.pi`** —— 那是 pi 的目录（它在里面找 `AGENTS.md`/`SYSTEM.md`、扫 `skills/`、把 `bin/` 当 `TOOLS_DIR`），塞无关内容迟早撞上它的目录扫描 |
| 文件名 | `<YYYYMMDD-HHmmss>-<sessionId>-<seq>.txt` | Ral 2026-09-15：「我们也该用 txt」。会话 id 里的 `/ : *` 先清洗 —— 不洗的话 `writeFileSync` 会写到子目录去或直接 ENOENT |
| 落盘内容 | **逐字原文** | 提示词里只剩摘要，文件是那段话唯一的完整副本 |
| 提示词里留 | **只有绝对路径**，不带摘录 | Ral 2026-09-11：「摘头摘尾 就没必要了」。引用块从约 2,600 字符降到约 300。⚠ 代价：换掉的是**整条消息**，所以混在粘贴前面的指令也一起进了文件 —— 模型必须先 `read` 才知道用户要什么 |

## 为什么是绝对路径

pi 内置 `read` 的解析是 `resolveToCwd(filePath, cwd)`（`pi-coding-agent/dist/core/tools/path-utils.js:72`）——
**绝对路径原样返回，没有目录限制**（实测 2026-09-11）。而 `<userData>` 在工作区之外，相对路径必然
解析失败。宿主自己那套受 workspace 根限制的文件工具够不到这里。

路径**单独成行**：嵌在句子里模型容易连标点一起抄进 `read`。引用块还明确点名用 `read` 工具 ——
不说清用什么读，模型会转头去问用户。

⚠ 这条**依赖内置 `read` 开着**。哪天把它从 `DEFAULT_PI_BUILTIN_TOOLS` 摘掉，这里发出去的地址就
变成空头支票（和 `out/chain/<id>.md` 那批没人写的地址是同一类死链）。

## 接线点

`sendAgentMessage()` 的 `trim()` 之后。那是用户文本进入 agent 的**唯一**入口，也是最后一个
「消息还是个纯字符串」的地方。

**渲染端那份不动** —— UI 与历史里仍是用户真正敲进去的原文；被换掉的只有交给模型的那一份。

## 降级

写盘失败 ⇒ **退回原文，不抛**。一次粘贴太大是可以降级的情形：原文进上下文只是占地方，
把发送整个打断是用户立刻看得见的故障。失败原因经 `error` 带给上游记日志。

## 不做的事

`.txt` 仅用于新生成的文件；已有 `.md` 文件与历史引用保持原样，不做迁移。

**不做清理**。文件是用户原话的唯一完整副本，而会话可能几天后才被翻回来；按时间删掉它等于让
历史里的引用变成死链。真要回收，那是一个独立的保留策略，不该藏在发消息这条路上。

## 验证

守卫 `check-long-paste.mjs` 跑真源码，覆盖：阈值两侧、落盘逐字、**引用块不含任何原文摘录**、绝对路径且单独成行、
文件名已清洗且扩展名为 `.txt`、写盘失败退回原文、以及**接线本身**（断开接线上面全部断言仍绿，而真实会话里一个字
都不会被转存）。已反向验证。**未跑 Electron E2E。**
