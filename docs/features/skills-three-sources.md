## #1 三个来源、目录和身份 — 已定 2026-09-16 · 已实现

**事实。** 两端现有 Registry 只扫描应用数据目录；名称为 `.agents/skills` 的兼容根也在 userData 内，并非当前工作区。现有会话文件服务已保留每个 Chat 的工作区绑定。扫描器还会写补充文件、清理 baseline，不能直接加入外部工作区路径。

**备选与建议。**

| 方案 | 得失 | 推荐 |
|---|---|---|
| 将第三目录直接加到旧 roots | 改动少，但扫描可能改写项目、没有会话边界 | 否 |
| 三个只读发现适配器 → 一个带会话上下文的目录服务；托管安装另行写入 | 多一层来源模型；复用现有解析/授权/引用能力，工作区不会被维护逻辑改动 | 是 |

设 `D` 为应用已有技能数据根：BL 为 `<userData>/cowork`，Cowork 为 `<userData>`。全局指**该应用当前 profile 的 userData**；跨账号共享，不擅自跨应用或跨 profile 合并。

| 来源 Tab（固定顺序） | 写入根 / 发现范围 | 切换行为 | 管理方式 |
|---|---|---|---|
| 全局 Skills | 主写入 `D/skill-library/shared/<skill>/`；云端明确 GLOBAL 的下发包也归这一层、保留托管来源；兼容 `D/skills`、`D/.agents/skills` 中已有已知全局技能 | 同 profile 退出登录、切换账号或工作区仍可用 | 本机导入、录制默认落这里；内置/远端托管条目保持来源标记 |
| 工作区 Skills | 该 Chat 实际工作目录的 `.agents/skills/<skill>/SKILL.md`；处在 Git 仓库内时，从该目录逐级向上到最近 Git 根的每个 `.agents/skills` | 只随该 Chat 的工作区变化；不读取其他 Chat 的选择 | 发现只读；提供打开文件/目录，用户在项目内修改 |
| 机构 Skills | `D/skill-library/<backend-account-scope>/<institution_id>/`；云包位于其受控 `cloud/` 版本目录 | 仅当前已验证账号与机构；切换立即换清单，撤权立即不可引用 | 云端下发只读；显示检查更新、同步/失败状态 |

工作区 root 必须复用真实文件工具的解析结果；未显式绑定时使用现有 default-workspace，标明“默认工作区”。Workbench 跟随当前选中 Chat；无 Chat 时使用应用默认工作区，并标明查看上下文。打开 Workbench 本身不得改变其他运行中 Chat 的工作区。

发现沿父级走到最近 Git 根（含根），子模块以自身根为界；非 Git 目录只读自身 `.agents/skills`。不递归搜索整个仓库的任意子项目。可递归读取所发现的 skill 根下技能目录，跳过无关依赖/版本控制目录；符号链接技能按真实目录去重、防循环，记录展示路径与真实路径并监听目标，既有文件访问授权仍适用。

**标准依据与产品选择分开。** [OpenAI Build skills](https://learn.chatgpt.com/docs/build-skills)（未标出版日期；检索 2026-09-16，原 Codex skills URL 重定向至此）说明：本地仓库从 CWD 到仓库根发现 `.agents/skills`；Skill 以含 name/description 的 SKILL.md 为入口，可有 scripts/references/assets 和可选 agents/openai.yaml；同名不合并，支持符号链接，正文按需读取。我们采用这些格式与发现规则。userData 全局位置、机构分发、完整清单保证和重载时序属于本产品设计；不额外引入 Codex 的 HOME/admin/system 四种位置作为新 Tab，也不声称完整实现 Codex 的配置/插件运行时。

| 规则 | 设计 |
|---|---|
| 解析 | 验证 YAML 和必需 name/description；无效项列出错误并从可用清单排除。可选 sidecar 缺失不算坏技能；有 sidecar 时读取 display_name/short_description/default_prompt 与 allow_implicit_invocation，不自动安装其依赖 |
| 分类与身份 | `layer=global|workspace|institution` 独立于 `kind=builtin|recording|markdown`、领域/domain 和托管状态；旧 builtin 推断不能代替来源判断 |
| 稳定引用 | 逻辑主键为 layer + rootIdentity + relativeSkillPath；机构再绑定 backend/account/institutionId/stableSkillId。序列化适配现有 ref，保留无歧义旧引用别名 |
| 同名 | 三层、同层不同目录均列出；选择器显示来源和相对目录。裸名称唯一才直接解析，多义则返回候选供选择；不按 Tab 顺序静默覆盖 |
| 迁移 | 已知 shared/builtin 保持原位置与引用；已知机构按原来源隔离。旧未归属录制/导入保留文件，以非 Tab 的“待归属 N”迁移入口展示，用户明确分配后才进入可用清单 |
| 机构旧本地条目 | 保留原机构内本地条目与授权，不误标“云端已发布”；默认不再把新本机录制静默写入机构分发目录。需要共享时走已有发布渠道 |
| 非破坏发现 | 不在工作区补写 README/AGENTS/CLAUDE，不删除 baseline，不自动拷走项目技能；应用私有缓存与安装账本留在 userData |

**代价。** 同名不再靠隐式覆盖消歧，需要带来源选择；保留兼容根会在详情多显示一个存储位置，但避免无必要搬动已有文件。

## #2 Workbench 展示与交互 — 已定 2026-09-16 · 已实现

**事实。** 旧页面将 domain、scope、未归属迁移混成导航层级，不能表达本次要求。两端统一信息结构，沿用各自控件、字体、主题与 IPC，不复刻整套新视觉系统。

**备选与推荐。** 保留来源下拉修改最少，但不能满足三个同级 Tab；推荐固定三 Tab + 两栏详情。领域/domain 降为列表筛选信息，录制运行约束照常生效。

~~~text
Workbench / Skills                     当前 Chat · Workspace / 当前机构
┌──────────────────────────────────────────────────────────────────────┐
│ 全局 Skills 3       工作区 Skills 3/4        机构 Skills 2           │
│ 来源目录 / 一句适用范围                       打开目录 / 检查更新    │
│ 搜索名称与描述           状态：全部          自动重载：已同步         │
├─────────────────────────┬────────────────────────────────────────────┤
│ code-review             │ code-review                 复制引用       │
│ 描述 · 可用             │ 工作区 · 项目规则 · 已自动重载              │
│ documentation           │ 名称 / 描述 / 来源路径 / 更新时间            │
│ 描述 · 可用             │                                            │
│ invalid-example         │ Skill 说明预览（纯文本/安全 Markdown）     │
│ 无法加载 · YAML 行号    │ 文件列表 / 打开 SKILL.md / 打开文件夹       │
│                         │ ▸ 加载诊断（折叠）                         │
└─────────────────────────┴────────────────────────────────────────────┘
~~~

页面稿中的数目、目录和文本是演示数据，不是实际运行证明。默认首次进入全局 Tab，此后记住上次选择；页面稿可用工作区 Tab 演示新增能力。Tab 切换只筛选 UI，**不改变 Chat 可用清单**。

| 区域 | 内容与动作 | 约束 |
|---|---|---|
| 上下文条 | 当前 Chat/工作区名称、机构名；完整路径可查看/复制 | 只显示已授权当前机构；没有登录明确显示未登录 |
| 三 Tab | 顺序固定；健康时可用数量，有异常时可用/总数 | 总数为已发现候选项，错误/未验证状态可解释，未归属单独迁移提示 |
| 搜索与清单 | 当前 Tab 内名称/描述搜索，状态筛选；行显示说明、加载状态、更新时间 | 无额外 Domains 大列；可用但网页不匹配的录制 Skill 仍在清单中，说明执行限制 |
| 详情 | 说明、来源、实际文件位置、更新时间、受控正文预览和文件列表 | 展示 userData 逻辑路径及复制实际路径动作；不显示签名 URL、token |
| 全局动作 | 导入 Skill、打开目录；本机可管理项保留打开文件、导出、删除；内置项保持既有管理限制 | 写入目标在对话框清楚标为全局，导入/删除后自动刷新；删除沿用确认和受控路径边界 |
| 工作区动作 | 打开当前 skill 文件/目录；目录不存在时给出应创建的标准路径 | 不因进入页面自动新建/迁移/修改项目文件；此轮不新增网页编辑器 |
| 机构动作 | 检查更新、失败重试、打开已安装文件夹（标只读托管）；详情显示机构/版本/同步时间 | 无本地修改云包或把机构包一键自动转全局；机构修改通过发布渠道 |
| 加载诊断 | root、ref、catalogRevision、skillRevision、解析错误/最后成功时间 | 默认折叠，供排查；不把技术字段铺满日常列表 |

| 状态 | 用户看到什么 | Agent 可用性 |
|---|---|---|
| 初次扫描 | 骨架 + 正在读取该来源；其他已就绪来源可浏览 | 发送前等待完整本地扫描，不能悄悄漏层 |
| 空目录 | 说明这一来源暂无技能；工作区显示 `.agents/skills` 路径 | 合法空集合 |
| 无搜索结果 | 清除筛选动作，来源总数保留 | 不影响完整 Chat 清单 |
| 坏 YAML/缺字段/断链接 | 错误行、文件位置、修复后自动重载提示；原有效缓存不伪装最新 | 对应项不可用，其他项可用 |
| 云同步中/离线 | 正在检查或离线，最后成功时间；无验证授权则“待验证” | 有效授权与完整缓存可继续用；未授权不可用，见 #4 |
| 账号/机构切换 | 旧列表和选中详情同步清空，新上下文重新加载 | 旧机构 ref 即时失效 |
| 窄宽度/键盘 | 至少 800×600 可用；清单→详情单栏可返回，Tab 独立水平滚动 | 不影响引用；Tab 方向键、Enter/Space、清楚焦点、Esc 返回 |

页面使用现有 12–14px 业务字体、冷灰底色与蓝色选中态，以留白和背景层级组织，不以边框、分割线或轮廓按钮表达层级；浅色/深色和减少动态效果均须覆盖。错误状态依靠文字及图标共同表达。

**代价。** 放弃原独立域名栏，领域筛选仍保留；三 Tab 明确来源但没有“All”第四 Tab，跨层总清单在 Chat 选择器和加载诊断中查看。

## #3 Chat 的最新完整清单 — 已定 2026-09-16 · 已实现

**事实。** 目前按当前网页 domain 筛选，且 BL 上限 40 / Cowork 上限 200，不能满足完整要求。两端运行时关闭 SDK 自动 skill 扫描，必须由宿主统一提供。

**备选与推荐。** 把所有正文塞入 prompt 容量高且会混淆“发现”与“使用”；推荐三层完整目录 + 正文/资源按需读取。所有可用项的 name、description、layer、qualifiedRef、入口路径、skillRevision 必须在该轮目录中，domain/调用限制作为元数据保留。sidecar 禁用隐式调用的技能仍列出并可显式引用。

~~~text
真实 Chat 工作区 + 当前机构授权 + 全局目录
                 ↓
    三来源扫描/托管同步 → 不可变 CatalogSnapshot
                 ├── Workbench Tab / 详情
                 ├── Chat 选择器 + pending turn prompt
                 ├── /view_context 下次输入
                 └── 引用解析 → 当前授权校验 → 正文/资源按需读取
~~~

| 契约 | 行为 |
|---|---|
| 快照 | session/workspace/institution generation + catalogRevision + 分层 ready 状态 + 全部条目；排序稳定，UI/发送/导出使用同一个服务 |
| 完整 | 不按网页 domain 或 40/200 上限删条目；分页取完云目录，明确分页完整性。无法扫描来源时不可标“完整” |
| 预算 | 先精简结构/重复字段，不悄悄省略技能。若完整清单仍放不进该模型可用窗口，明确说明目录超预算并阻止这次发送，允许选择更大窗口或调整来源目录中的技能；不回退为隐形截断 |
| 正文 | `get_skill_contract`/对应读取工具支持三层 Markdown 和已有录制类型；长正文可分页连续读取，不把截断正文标成全文 |
| 实际使用 | 复制/选择 ref 引用具体技能；原有录制需匹配 domain/执行条件，普通 Markdown 不因无 recipe 被拒绝 |
| 缓存 | 按 ref + skillRevision + context generation 缓存；技能更新清除该条正文/预览/运行前缓存，不重置整段 Chat |
| 安全 | 读取/运行前重新校验机构授权和工作区归属；有文件不代表可引用；扫描/预览不运行脚本 |

可用清单指三层**当前有效且可读取**条目；坏包、未归属、撤权和未验证项不注入指令，清单诊断仍列明数量与原因。这个定义不得用于掩盖总数截断或未扫描来源。

**代价。** 完整清单比相关度挑选消耗更多上下文；目录极大时发送会显式失败。这是用户完整性要求的代价，不用静默遗漏规避。

<a id="s4"></a>
## #4 自动重载与机构同步 — 已定 2026-09-16 · 已实现

**事实。** 本地更新尚无通用文件监听；Cowork 现有 60 秒是触发去重时间，不等于轮询；BL 尚缺 Skills 下载适配器。云端同版本替换 ZIP 时，现有仅比较 version 的更新判断会漏掉变化。

**备选与推荐。** 只在打开页面/新会话重扫无法兑现自动更新；推荐 watcher + 每次发送前新鲜度校验 + 真正的云轮询，局部重载并原子发布快照。

| 触发 | 建议行为与时序 |
|---|---|
| 本地目录/文件变化 | 监听 SKILL.md、agents/openai.yaml、scripts/references/assets 与其他包资源；300ms 合并连续事件。添加、删除、rename、原子保存、symlink 目标变化均使对应条目失效 |
| 缺失目录与监听恢复 | 监听最近存在父目录；目录新建自动发现；系统恢复/重新聚焦补扫描。监听失败显示状态，发送前仍强制完成该上下文扫描 |
| 内容版本 | 根据包文件清单和内容指纹生成 skillRevision；资源变化也触发正文/工具缓存失效，不能只看 mtime 或 version 字符串 |
| 本地重载目标 | 常规本地文件稳定后 2 秒内 UI 与目录更新；这是待验收目标，不是已测性能。慢盘/大文件可显示“正在重载”，发送等到完成 |
| 编辑错误 | 稳定解析失败后对应技能退出可用集合并显示错误；旧成功文件可留作诊断/恢复，不能继续标为最新版。其他技能不中断 |
| 实际模型请求 | 已发出的请求不可修改；每次后续模型请求/新用户发送前在安全边界更新目录。已有正文过期时记录更新并按需重读，历史内容不冒充当前指令 |
| 正在执行脚本 | 一次已开始执行固定同一包 revision，不中途替换文件；后续新调用取新 revision。若机构撤权则取消/阻断受影响调用，不能以“固定版本”绕过授权 |
| 机构轮询 | 登录且机构有效时每 60 秒检查，启动/切换/恢复网络/手动重试立即检查；单飞请求，退出停止，带 generation 丢弃过期响应 |
| 安装与删除 | 私有 bucket 签名下载 → 字节/可靠 hash 校验 → 安全解压 staging → 包格式验证 → 不可变版本目录 → 原子激活 → 重载。失败保留原有效版本并说明错误；下架仅撤销受控映射，不删用户文件 |
| 离线/授权 | 全局/工作区离线可用；机构仅在既有未失效授权下使用验证过的缓存并标离线，401/403/退出/明确撤权立即不可用。不得因网络失败推断授权成功 |
| 工作区或账号切换 | 新 generation；旧结果不能回写。工作区只失效受影响 Chat；全局技能更新广播相关 Chat；不以 resetSessions 丢掉聊天历史 |

云端配套契约（按现有接口增量兼容，**无需新增 Skill 表**；Workflow 表不变）：

| 接口/数据 | 必要要求 |
|---|---|
| catalog / resolve | 显式 GLOBAL 或当前 INSTITUTION，机构身份从各后端已验证的请求上下文取得（Mono 使用 x-iid，BL 需兼容新增机构筛选）；服务端先授权限定范围再分组，不能跨机构同名覆盖。所有分页可穷尽 |
| download-url | 返回稳定 skill_id、scope、institution_id、version、hash/可靠 contentRevision、size；下载签名 URL 不进入模型上下文 |
| check-updates | 新客户端提交来源限定的稳定 ID + 已安装 contentRevision；version 不变但内容变仍返回更新；下架独立返回；旧输入格式保持兼容 |
| register / 发布 | 每次包变化生成可靠内容 revision；优先以服务端验证的 SHA-256 绑定包字节，不把可选客户端自报 hash 当唯一证据；既有无 hash 包补验证后才激活 |
| 同名与上限 | 同名跨来源都有 ID；当前机构不同同名路径也有独立身份。服务端 2000/500 等安全限制必须显式报错/分页分批，不无声截断 |
| 客户端适配 | Cowork 复用 scopedSkillSync 并补真轮询/内容版本；BL 补 Skills API adapter 与安装链。两端都复用现有账号与机构授权边界 |

<a id="s5"></a>
## #5 view context 的可核对证据 — 已定 2026-09-16 · 已实现

**事实。** 两端现有 `/view_context` 复制当前 system、有效历史和 pending 输入，语义是**下次发送的上下文**。不能用它声称过去已经发送过某个版本，也不能把目录出现当成正文已读。

**备选与推荐。** 只在诊断面板重建一份“看起来加载了”的列表无法证明真实输入；推荐复用发送的同一 snapshot/formatter，实际发送保留 request 与 catalog revision 的对应关系。保留现有命令和有效历史行为。

| 导出区域 | 内容 | 真实性约束 |
|---|---|---|
| 当前待发送目录 | workspace 解析结果、机构身份、catalogRevision、三层可用/错误数量、完整条目（name/description/ref/source/path/revision） | 与该 Chat 实际构造 pending prompt 使用同一份快照 |
| 正文使用说明 | 未请求正文的仅“已进入清单”；实际读取后才有具体 ref/revision 和正文读取记录 | 不生成虚构“已读取”回执 |
| 与历史区分 | 历史轮次保留历史版本；当前目录明确替代旧目录用于后续选择 | 不改写旧历史，不以新扫描结果冒充已发送内容 |
| 更新竞态 | 导出后发生变更则发送取新 revision；检查日志可对应实际发送 | 一致性测试固定同一 revision；变化后预览明确“下次发送将更新” |
| 未完成扫描/错误 | 明确 pending/error 状态或等扫描完成；指出哪层未就绪 | 不把空列表伪装成功 |

Ral 的人工验收路径（待开发完成后执行）：

1. 三层各准备一个可区分的有效 Skill；同名变体也各保留一份。
2. 在选定 Chat 运行 `/view_context`，检查三层数目、每项 source/ref/path 与 Workbench 一致；本步只证明清单。
3. 在同一 Chat 显式引用三个来源的技能，检查实际读取到各自正文。
4. 外部编辑其中一个 SKILL.md，再运行命令、发送一条新消息；目录 revision 和该 Skill 内容应更新，无需新开 Chat。
5. 切换该 Chat 工作区、切换账号/机构再查看：全局保留，工作区按 Chat 变，旧机构退出。
6. 检查坏 YAML/删除/同版本机构包更新，确认 UI 状态与模型实际可用清单一致。

**代价。** 必须记录模型输入使用的目录版本，而不是仅验证渲染组件。首次导出会等目录准备完成；不会自动运行任何技能作为“加载测试”。
