# Evidence

- A successful completed turn claims one durable SQLite receipt keyed by
  `(thread_id, turn_id)` in the same transaction that produces `idle + unread`. Failed,
  interrupted, archived, duplicate, and synthetic-ID completions do not emit an alert.
- The versioned migration creates the receipt schema and backfills existing
  `last_completed_turn_id` values once, while normal schema finalization only ensures the table.
  Retained older databases therefore upgrade without replaying historical completion alerts.
- App Server notifications, trusted Hook deliveries, and guarded polling reconciliation share the
  same receipt claim. Duplicate same-source delivery, cross-source Hook/App Server races, repeated
  polling, repository restart, and Hook ACK replay cannot emit twice.
- The original P2 teardown race is resolved: once SQLite returns a claimed intent, Main dispatches
  it even if the observation context was aborted during the write. Renderer broadcasts and title
  enrichment remain fenced by the active context. A shutdown-during-write regression covers this
  ordering.
- The original P3 cross-source coverage gap is resolved by a repository regression proving that a
  later Hook completion for an App Server-claimed `(thread_id, turn_id)` returns no second intent.
- Native notification assembly and sound playback are centralized in
  `src/main/notificationcenter/notify.helper.ts`. It uses current-language strings, a bounded
  sanitized title or localized untitled fallback, and a silent system notification containing no
  prompt or response content.
- The supplied WAV is copied unchanged to the packaged external sound resource. Main resolves
  separate development and packaged paths, invokes macOS `afplay` and Windows
  `System.Media.SoundPlayer` without a shell, and isolates notification and playback failures.
- The Windows AppUserModelID matches the production/development IDs generated by the builder.
